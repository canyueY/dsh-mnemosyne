# Mnemosyne 综合改进方案

日期：2026-11-01。性质：下一阶段产品与工程规划，不代表已实现、已验收或已发布。

## 1. 综合结论

Mnemosyne 下一阶段应围绕一条用户可验证的闭环组织建设：**经历被正确记录 → 需要时找回证据 → 分清历史与当前 → 接受纠正 → 后续回答和行为体现变化。**

11 份文本包含 9 份具体项目对比、1 份优势分析、1 份评论反馈方案。它们反复提出的需求可以归并为八条工程主线，无须把九个项目各自的模块体系全部搬进来。

建议定位为：**面向长期项目和个人 Agent 的、可信且可纠错的长期认知基础设施。** 先用跨会话工作、事实更新和纠错证明价值，再逐步支撑生活经历、内容学习和有限行为改进。模块多、引用多、图谱大、神经网络复杂，都不能直接证明记忆效果更好。

本方案依据所给文本，并抽查当前本地 Node 2.0 的实现和实现报告。外部项目的版本、性能、许可证及实现描述沿用输入材料，未重新审计其远程仓库；材料中的行动建议视为待评估方案，不视为用户要求执行的指令。相互转述的建议不按独立“投票”计算可信度。

## 2. 当前基础：保留已有能力，补齐使用链路

本地实现已经具备以下基础，后续应复用并补接入和验证，不能再次作为全新系统建设：

- Observation／Evidence／Claim、来源依赖、验证、版本及 ChangePlan 采用与回滚。
- Bank 隔离、权限门控、迁移 staging、已有备份与恢复机制。
- 时间信息、情绪候选、画像假设，以及带预算的任务决策闭环。
- 分类反馈；“有用”、任务成功和自评不直接提升事实可信度。
- 固定 heldout／regression 验收、有限规则采用与回滚、依赖敏感的精确缓存。
- 持久任务队列的预算、冷却、重试、租约及提交条件检查；Manifest、onboarding 诊断与验证入口。

但当前基础与目标体验之间仍存在明确距离：

1. 普通 search／retrieve 主要返回记忆候选，不自动执行新任务闭环。排序靠前不能直接解释成“当前事实已确定”。
2. 检索评分中的证据数量是排序信号，不能代表独立支持或事实概率。当前时间降权与状态过滤也不等于完整的时间适用性裁决。
3. 默认 semantic scorer 使用本地哈希表示，不能据此宣传高质量语义理解；已有 FTS 也不等于完整多路召回、融合和反证保护。
4. 现有巩固主要是 rule_v1 截取式情节候选，保留摘要来源与有损标记，但尚不能据此宣称完成多层 Dream 和长期认知整合。
5. 现有上下文预算是内容 token 估算，未等同于包含标签、头部、工具描述、历史及输出预留的完整请求预算。
6. Trace 的 cost 字段不等于已完成宿主与 Node 共用的成本账本；已有迁移 checkpoint 不等于完整会话恢复。

对于会话 Seen Ledger、派生物新鲜度、完整消费水位、跨设备治理等能力，本次不凭有限搜索认定“完全不存在”；应逐项核实其接口、主链路接入及故障用例，再决定补实现还是补验收。

当前 README 标识 Node 2.0。输入中出现的“3.0”作为未来架构设想处理，不能据此宣布版本完成。

## 3. 统一架构与责任边界

保持 **宿主／数据适配器 → Mnemosyne Node → Node 管理的 Memory Bank**。Memory Bank 是数据目录，不新增第二个认知服务。项目隔离沿用 Bank 机制；跨设备多 Node 是另行治理的问题。

Node 内部按职责组织为：采集与来源、证据与版本、检索与选择、上下文与恢复、巩固与候选学习；预算、权限、审计贯穿各环节。这是职责划分，不要求拆成独立微服务或新增同等数量的数据库。

权威按数据领域明确：

- 原始文章、日志、书籍由其来源系统管理；Node 保存可定位的版本快照或引用及采集证据，不冒充原作者。
- Node 负责认知记录、验证状态、版本关系和候选规则的权威管理。
- 执行器负责配置及实际操作权限；宿主负责会话、调用与上下文交付。Node 的判断不能绕过执行权限。
- 摘要、画像、图谱、向量、索引、身份快照均为可追溯的派生视图，不能形成平行的事实权威。

至少分开管理四类信息：**认识状态、用途与显著性、来源信任与可见范围、运行及派生新鲜度**。不要用一个 confidence 或 active 状态包办全部含义，也不必为每个维度另造状态机。

## 4. 必须先统一的取舍

### 4.1 召回不等于强化，强化不等于增信

区分检索命中、上下文交付、用户使用反馈和任务结果。读取频率用于曝光与调度分析；有归因的效果可用于用途排序；事实状态仍由证据验证决定。同源转发、摘要复述和重复导入不能增加独立支持数。[S04、S05、S07、S09、S10]

### 4.2 原始证据保留，不等于永不删除

巩固不得静默覆盖原文；修改以新版本、撤回和替代关系表达。但用户授权的删除、保留期限和敏感信息处理仍然生效。删除后保留必要的不可复活标记，阻止缓存、备份恢复或设备同步悄悄重新引入；相关派生物失效。来源已不可访问时应如实说明，不能假装证据仍可核验。[S01、S04、S07、S08]

### 4.3 多路召回负责找候选，证据选择负责判断适用性

RRF、向量相似度、图传播与最近时间都不能代替事实裁决。冲突双方、否定条件和关键反证应有保护通道，不能仅因分数低被截掉。预算耗尽意味着检查未完成，应返回限定结论或未知，不能把“停止查找”写成“反证不存在”。[S02、S04、S07、S10]

### 4.4 自动整理先产出派生物与候选，不自动重写人格

摘要、结构模式、行为规则、主体立场、客观事实是不同产物。用户的一次表达、外部作者观点、正面反馈或一次执行成功，均不能直接形成永久人格或事实。用户模型、Agent 自我模型、价值假设和宿主硬约束分开；记忆中的指令文本不能获得宿主策略权限。[S02、S03、S06、S08、S09]

### 4.5 经验类比用于提出实验，不用来证明理论成立

神经可塑性、激素、MirrorNet、DefectNet 等只保留为可选研究思路。复制权重不证明自我意识，降低预测误差不证明真实理解，改变立场不自动意味着成长。核心可靠性不得依赖这些假设成立。[S06、S08、S11]

### 4.6 保持基础契约兼容，不把“冻结”理解成禁止修复

保留既有 API 与数据边界；必要的安全修复、缺陷修复和有版本迁移仍可推进。旧系统先只读接入与影子比较，明确切换写入权，避免双重认知权威和重复上下文注入。[S02、S04、S07、S08、S10]

## 5. 八条工程主线

### W1｜可信数据、原始经历与派生一致性

**优先级：P0；依赖：现有来源、Evidence 和权限基础。**

补齐原始消息、工具请求／返回、文章、日记与书籍片段的稳定 ID、来源版本、定位信息、内容哈希、采集时间和范围。保留前后文，支持附件引用与生活情境；无须把所有原始文件强制迁入 Bank。

建立证据覆盖描述：读了哪些页、时间段、文本、音频或画面，缺失什么。来源“声称了某事”和“某事已独立验证”分别表达；只见字幕时，不能声称看过画面。覆盖是否足够按具体 Claim 判断。

为摘要、画像、索引、图谱和缓存建立可查询的依赖清单：来源修订、处理器／配置版本、提取游标、新鲜度。源修改或撤回后，先让旧派生物失去“当前可用”资格，再排队重建；不能等重建完成才承认过时。哈希证明所保存内容的一致性，不证明原作者身份或内容真实性。

外部工作区与数据库先登记信任及读取范围；未授权时不采集、不注入、不执行 Dream。授权采集也不等于来源内容已经成为事实。

**交付与验收：** 原文 → 派生物 → 回答的可追溯链；源文件改动、撤回、缺页、缺模态、重复导入、跨 Bank、循环引用和删除后恢复均有用例；同源资料不因多次导入变成独立支持。[S01、S02、S03、S04、S05、S07、S08]

### W2｜时间语义、冲突处理与当前答案选择

**优先级：P0；依赖：W1 的可用证据与范围。**

复用现有 Claim、Verification、ChangePlan 和 CognitiveLoops，为正常问答增加明确的“当前答案选择”入口。普通搜索继续保留候选检索职责；需要判断当前状态时，宿主显式调用选择入口，避免悄悄改变所有旧接口语义。

分别处理发生时间、记录时间、有效区间和查询时间，时间未知时保留未知。将冲突分类为：时间变化、情境差异、主体差异、作者分歧、真正矛盾、主体立场变化及信息不足。当前回答与历史回顾走不同视图；不能一律“最新覆盖旧的”。

结果携带采用项、未采用项、证据、有效范围、反证检查状态与 reason codes。允许回答“历史上是 A、目前有 B 的证据”“仅对这个情境成立”“资料不足”。解释“为什么变化”时，区分观察到的先后、当事人提供的理由和系统推测的原因。

**交付与验收：** 暂时偏好不泛化成永久偏好；旧地址与现地址、不同项目限制、否定与双重否定、迟到消息、作者观点不被误合并；纠正后普通回答、派生摘要和缓存体现新状态。截断或预算不足不产生确定性结论。[S02、S03、S04、S07、S08、S10、S11]

### W3｜按需检索、多路融合与检索评测

**优先级：P1；P0 先保证范围、时间过滤及反证不会漏接。依赖：W1、W2 与固定评测集。**

按增益逐步增加通道：先完善 FTS／词法和中文规范化，再按需加入真正的本地或可选远程向量通道，最后评估实体图与有界图扩展。保留当前轻量路径，不强制所有用户安装大模型或向量服务。

多路召回可用 RRF 融合，参数经固定样本标定，不照搬报告中的权重。时间条件和 Bank 权限尽可能在候选召回前约束，汇总后再次检查；回顾类查询按时间段保持代表性，而非总是偏爱最近记录。

实体合并、共现、支持、反驳、因果假设分开。标准 PPR 的概率转移通道保持非负；反驳关系走显式反证通道，不直接复制带负权的随机游走设计。先证明实体和边的质量，再决定是否上线图传播。

**交付与验收：** 记录每通道候选及融合理由；支持关闭任一通道做消融。用同一数据比较当前基线、词法改进、向量及图扩展的候选覆盖、最终判断、反证召回、延迟和成本；无可测增益的复杂通道暂不上线。[S01、S04、S05、S07、S10]

### W4｜上下文、会话连续性与任务恢复

**优先级：P0；依赖：W1、W2，预算规则由 W6 提供。**

上下文分为稳定且简短的快照、当前任务骨架、按需证据卡片。身份和工具说明保持稳定前缀；动态记忆放在动态区。用户约束与助手自报进展分别保存，避免把“我完成了”直接当成验收结果。

实现会话生命周期采集和去重：持久化前捕获原始消息；模型调用前构建上下文；压缩、重启或换会话后恢复任务目标、约束、已验证进展、未决问题与待确认外部操作。

Seen Ledger 只记录可观测事实，例如哪些记录被读取、哪些卡片已交付及对应修订。宿主交付回执不证明模型理解或实际使用，不因重复交付自动强化事实。

对任务保留 Checkpoint／Handoff／Execution Ledger：工具已请求、已返回、外部效果已确认分别记账。外部调用超时且效果未知时，先核对回执或状态，不能盲目重试造成重复发布、扣费或写入。

**交付与验收：** 长会话压缩后仍保留关键否定、失败／跳过计数、限制和下一步；跨会话恢复无重复采集；不同会话不会互相继承未授权承诺；强制中断后恢复不重复外部副作用。[S02、S04、S05、S07、S10、S11]

### W5｜分层巩固、用途视图与可逆遗忘

**优先级：P1；依赖：W1、W4、W6。**

在现有 rule_v1 基础上，建立“原始经历 → 原子候选 → 主题／项目派生摘要”的巩固流程。日记可按周、月等周期汇总，书籍可按章／段定位，但周期和层数是任务选择，不是必须全部常驻的层级体系。

借鉴 soul／user／project／fact／lesson／topic／rules 作为用途视图，而非七个数据库或七种真实性。身份快照是现有受控记录的派生视图；摘要、图式和可采用规则各自验收，不能混为同一种“抽象”。

会话巩固以实际创建、读取或交付的记录为输入，空闲运行、前台抢占。复用现有任务队列；为新增巩固和效果消费补齐适当的幂等键、独立水位及写入保护。用途统计与共检索建边各有消费者水位；效果写入和水位推进同事务提交。长期运行处理器不能仅靠最终任务状态检查防止过期租约写入，实际数据提交也需验证租约代次／版本。

遗忘采用类型化降温、归档和可逆折叠，优先降低注入频率而非删除证据。罕见但重要的事件可固定保留；事实不会因为“30 天没读”自动变假。拒绝未验证的重复阈值、固定半衰期及三次召回即晋升。

**交付与验收：** 摘要保留失败数与关键否定；派生物可从来源重建；中断重跑不重复强化、不漏消费；并发与过期 worker 不能提交旧结果；前台请求可暂停后台任务。[S01、S02、S04、S05、S06、S07、S08]

### W6｜预算调节、成本账本与认知可观测性

**优先级：P0 的限额与降级；P1 完善调度标定。依赖：宿主与 Node 的调用回执。**

将已有预算与 MetaQueue 接到正常链路：限制检索轮数、耗时、候选规模、上下文占用、后台任务与外部模型调用。观察边际收益，选择继续查证、缩小范围、延后巩固或停止；停止不等于任务成功。探索比例、冷却和触发阈值按事件与误判数据标定，不复制固定“几次／几小时”。

成本分开记宿主推理、Node 外部模型、向量处理及重试。分别标注提供方实测、估算与未知；拿不到宿主 usage 时显示未知，不能记为零。Node 只能约束自身及宿主配合的调用，不能保证用户整个账号账单。

完整请求预算包含稳定前缀、历史、工具、记忆卡片、标签与输出预留。精确 tokenizer 不可用时明确是估算并保守预留；不能把估算上限宣传成真实 token 硬保证。硬限额优先采用可执行的调用次数、输出长度与运行时限额。

认知健康探针验证真实读写、来源可访问性、索引版本、队列积压、worker 完成、执行回执和备份恢复。状态区分 OK／WARN／ERROR／PENDING／UNKNOWN；“接口返回正常”不是功能正确的充分条件。探针本身也要通过故障注入，防止监测系统永远报绿。

**交付与验收：** 限额触发可预测的降级；usage 缺失不显示免费；付费提供方超时结果未知时不盲重试；模拟索引过期、worker 失联、数据库不可写和回执缺失，状态及用户提示准确。[S02、S04、S05、S06、S09、S10]

### W7｜执行结果、分类反馈与有界学习

**优先级：P1；依赖：W1、W2、W4、W6。**

复用 TaskFeedback、LearningProposal、ValidationSuite 和采用／回滚接口，先让它们服务真实任务中的一个有限策略改进，而不是再造一般学习引擎。

执行链统一区分“提出计划、配置保存、运行时采用、执行确认、效果观察、长期规则采用”。Node 提供依据和约束，执行器检查能力、前置状态及并发版本。可借鉴参数 explain／preview／apply／verify／history／rollback，但不把执行器搬入认知核心。

反馈分别进入事实纠错、表达偏好、任务结果、执行故障、约束违反和未分类通道。沉默、满意、拒绝、立场改变均不自动成为正负奖励；归因默认未解决，记录混杂因素与候选故障阶段。只在有明确证据时改变具体认识或策略。

规则候选先影子运行，在固定独立样本和回归样本上比较；通过版本、权限与验收门槛后才采用。配置更改一次不变成永久人格，合成样本收益也不冒充真实用户收益。

**交付与验收：** 保存成功而运行时未采用必须可见；执行成功而效果未知保持未知；污染测试集、自评 passed、重复同源反馈、跨 Bank 证据和过期规则不能通过采用；回滚不覆盖其他人后续合法变更。[S03、S06、S08、S09、S10、S11]

### W8｜接入、迁移与可解释的产品体验

**优先级：P0 的可安装／演示；P1 的领域适配与解释；多设备后置。依赖：对应核心能力通过验收。**

领域适配优先选择一个真实需求：长项目工作、文章／视频学习、日记或书籍。日记保存经历与情境；内容学习保留作者观点和覆盖范围；书籍保留章页段锚点。统一进入既有认知契约，不为每个领域建立平行 Belief 库。

跨设备同步不直接合并 SQLite 或依赖 Git 解决事实冲突。后续再设计设备身份、增量事件、独立导入去重、逻辑顺序、删除标记与冲突保留；逻辑时钟只解决事件顺序，不裁决事实真假。

**交付与验收：** 新用户从空环境完成“记录—重启—查询—纠正—再查询”；旧库迁移可解释失败、可恢复、无重复；解释视图能打开对应来源版本；未经授权的外部工作区不进入记忆。[S01、S03、S04、S05、S07、S08、S10、S11]

## 6. 最小契约：扩展既有对象，不建设第二套认知数据库

以下是逻辑数据契约，优先映射到已有模型、元数据和版本表；只有约束与查询需要时才新增索引或表。

1. **SourceRef／Coverage：** 稳定来源 ID、根来源与修订、定位、哈希、主体与来源角色、采集时间、已覆盖和缺失范围。
2. **DerivationManifest：** 输入依赖及其修订、处理器／配置版本、处理水位、产物 ID、新鲜度及失效原因。
3. **DecisionEnvelope：** 查询意图与时间、候选、采用／未采用理由、支持与反证、适用情境、未知项、预算终止原因。
4. **ContextManifest／Checkpoint：** 会话和任务、约束、证据修订、已交付卡片、已验证进展、未完成项及未知外部效果。
5. **Action／ExecutionReceipt／Outcome：** 关联 ID、权限与状态版本、预览、执行器回执、实际采用状态、效果观察及回滚前置条件。
6. **Utility／FeedbackEvent：** 目标记录或执行、反馈类别、来源、结果、归因状态、消费水位；不直接写入事实可信度。

共用稳定事件 ID、Bank、生产者、记录时间、幂等键和契约版本。发生时间未知时不要用接收时间伪造。至少一次投递配合幂等消费即可，不承诺外部系统无法保证的全局“恰好一次”。

## 7. 实施顺序与阶段门槛

### M0｜建立基线与最小契约

盘点八条主线的“已有／部分接入／待补／待验证”，冻结本轮对比样本和评测方法，保存当前行为基线、API 与数据版本。先明确来源、反馈和执行回执契约及基础预算。输出可复现基线，不新增研究网络。

### M1｜可信可用的最小发布

完成 W1、W2、W4、W6 的最小链路与 W8 安装演示。主验收脚本为：记录一条有情境的认识 → 重启 → 正确召回 → 新信息改变适用状态 → 纠正 → 派生物和缓存失效 → 后续回答引用新版本并解释历史。另覆盖中断恢复和预算降级。

**门槛：** 关键反例通过、兼容性通过、干净环境示例可复现。对功能或来源未知的环节明确标注，不以文档或接口存在代替验收。

### M2｜持续运行与低成本质量提升

开展 W3 多路检索消融、W5 巩固与水位、W6 完整成本与健康探针、W8 来源解释和渐进迁移。先上线有可测增益的通道；图传播与较重模型可继续保持关闭。

**门槛：** 同预算质量改善或同质量成本降低；并发、崩溃、租约过期和来源变更后不重复消费、不静默使用旧派生物；前台体验不被后台巩固拖垮。

### M3｜一个领域与一个有限行为闭环

选择一个领域适配和一个可回滚策略，以 W7 贯通建议、执行、效果和候选学习。先用隔离执行器验证协议，再在明确授权范围内检验实际效果。

**门槛：** 独立样本有效、回归无不可接受损失、行为效果有实际观测、归因限制明确、回滚可用。不是仅在数据库中保存了一段“反思”。

### M4｜可选研究与多设备

按真实需求开启主动提问、预测误差调度、情绪状态、自我模型或多设备；神经可塑性保持独立实验路线。前面阶段的可靠性不能依赖本阶段完成。

不承诺未经估算的日历工期；完成 M0 的现状盘点与工作量拆分后再排具体日期。上述阶段也不直接等同于发行版本号。

## 8. 验证方案与效果指标

### 固定场景集

建议先建 40 个固定场景，分为基础回归 20 个、独立评估 20 个；同一来源的改写和摘要不得跨分区伪装成独立样本。再按失败扩充，数量本身不代表覆盖充分。

- 语义与时间：否定、主体、不同情境、临时偏好、迟到记录、历史／当前、作者观点和来源分歧。
- 证据与更新：同源重复、证据环路、来源缺失、撤回、源修订、派生失效、缓存失效与恢复。
- 会话与执行：压缩丢失关键条件、重启恢复、工具请求／回执分离、超时未知、重复投递和禁止重复副作用。
- 运行与治理：跨 Bank、未授权来源、预算耗尽、usage 未知、故障探针、并发版本及租约过期。
- 学习与迁移：自评不能增信、反馈归因未知、验收污染、规则回滚冲突、断点导入、删除标记防复活、旧版本兼容。

在临时 Bank 中运行单元、契约与集成测试；数据库和队列用故障注入，发布包用干净环境冒烟；不在个人 Bank 上注入故障。选定领域后再增加脱敏、经授权的真实任务留出集。

### 指标定义

- **当前答案适用正确率：** 标注为可判定的场景中，选对主体、情境、时间状态的比例；另报未知回答是否合理，防止全部回答未知刷安全分。
- **反证召回与处理率：** 样本中存在的关键反证被召回并进入判断的比例，分别统计召回与采用阶段。
- **来源可追溯率：** 返回的需证据 Claim 中，能定位到对应版本、权限允许且来源链有效者的比例；可追溯不代表事实一定为真。
- **纠错复发率：** 已接受纠正后的后续适用查询中，再次使用旧错误结论的比例。
- **派生一致性：** 来源改变到失效标记的时间，以及过期产物被误当当前证据使用的次数；与重建耗时分开统计。
- **连续性与执行安全：** 恢复后约束保留、任务继续成功，以及重复／未知外部效果的正确处理率。
- **成本与性能：** 每任务和每回合的实测／估算 token、调用次数、P50／P95 延迟、后台资源、模型账单已知范围；同时记录结果质量与未知项。
- **有限学习净收益：** heldout 增益与 regression 损失分别报告，展示规则改进是否改善任务，而非只改善内部预测损失。

关键权限越界、未授权改写原文、错误事实晋升和重复外部副作用在固定发布用例中要求零失败；这是测试门槛，不是生产环境永不出错的承诺。其他目标先测基线再制定，不复制外部项目的自报指标。

## 9. 暂缓与独立实验清单

- 不为每个借鉴对象新增一个服务、数据库或全套网络；不同时运行多套正式记忆注入器。
- 不把“读取越多越真”“引用越多越真”“新信息一定覆盖旧信息”作为规则。
- 不让不可核验的内容、模型自评或单次好评自动成为证据。
- 不把神经权重、人格快照或主题摘要作为事实权威。
- 主动提问采用问题预算、冷却、可拒绝与发送回执；“准备了问题／发送／得到回答”分开，不按提问数量奖励。
- 预测实验分开保存预测、实际结果和误差；预测新颖性不等于真实性。快状态、中期策略与慢身份分开更新。
- 神经实验必须有不可变训练清单、完整权重／偏置／优化器校验、基线快照、独立验收和回滚；离线训练可中断，队列确认与检查点一致。不得只抽查少数参数的 NaN，或把学习率倍率写成人格形成的证明。
- 多设备与联邦必须先解决身份、撤回、幂等、冲突和权限；不直接同步可写 SQLite。

若以后复用外部代码，应另行核对具体版本、许可证和依赖。本次只提炼机制，不引入外部运行依赖。[S02、S03、S04、S06、S08、S09]
